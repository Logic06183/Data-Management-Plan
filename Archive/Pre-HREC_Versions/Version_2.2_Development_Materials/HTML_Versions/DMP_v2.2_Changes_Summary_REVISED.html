HE²AT Center Data Management Plan v2.2 - Changes Summary

Document Version: 2.2 - Revised
Date: August 2024
Purpose: Summary of changes implemented based on stakeholder meeting feedback

Executive Summary

Version 2.2 of the HE²AT Center Data Management Plan introduces comprehensive updates to address the cloud migration implementation and enhanced data governance procedures. Version 2.2 of the HE²AT Center Data Management Plan has been revised following stakeholder feedback to emphasize the transition period nature of the infrastructure changes and streamline the document for ethics submission.

Key Revision Principles

  • Emphasis on Year 5 transition period rather than permanent hybrid system
  • Focus on data management procedures rather than contractual details
  • Universal DAC review requirements for all data access
  • Simplified documentation for ethics review

Major Changes Summary

Section-by-Section Changes

Section 3: Background and Overview

  • Added Section 3.4 emphasizing the transition period nature of infrastructure changes
  • Clarified that Year 5 represents a temporary dual-capability period
  • Removed detailed contractual language and replaced with focus on data management objectives

Section 4: Data Types

  • Updated all data storage references to include "during the transition period"
  • Emphasized dual infrastructure capabilities as temporary measure
  • Removed complex ownership language and simplified to essential ownership statements

Section 5: Data Transfer and Ethics

  • Detailed DTA contractual requirements replaced with simplified compliance focus
  • Maintained ethics approval references and procedures

Section 6: Pre-processing and Harmonisation

  • Added transition period infrastructure references
  • Emphasized automated backup and enhanced security during transition

Section 8: Data Analysis Platform

  • Included cloud-based computational resources with GPU acceleration
  • Noted enhanced capabilities available during transition period

Section 10: Data Sharing

Critical Change: All projects, regardless of whether they involve internal HE²AT Center Consortium members or external researchers, must go through the DAC for data access approval. This ensures equitable data sharing and maintains comprehensive tracking of all projects using the data.

Section 12: Governance and Compliance

  • Complex DAC procedures with different paths for consortium vs external researchers
  • Unified DAC review process for all data access requests
  • Emphasized consistent application of ethical and scientific standards

Section 14: Restricted Data Access

  • Enhanced cloud security measures clearly outlined:
    • AES-256 encryption for all data
    • 24/7 Security Operations Centre monitoring
    • Advanced threat detection systems
    • Automated compliance reporting
    • Enhanced disaster recovery capabilities

Section 15: Roles and Responsibilities

  • Specific individual names and contact details in main table
  • Generalized institutional roles with key functions
  • Contact information maintained in separate updateable document

Section 17: Cloud Migration Implementation

  • Entire section removed from main document
  • Content restructured and moved to Annex 1: Transition Implementation Details

Transition Period Emphasis

Key Transition Messages Throughout Document

  • Year 5 represents a temporary transition period, not a permanent change
  • Goal is complete migration of all sensitive health data to cloud by end of Year 5
  • Dual infrastructure capability maintained only during transition for continuity
  • Enhanced security and compliance measures throughout transition

Data Provider Communication

New Annex 1 includes a comprehensive communication framework with:

  • Generic email template for data provider updates
  • Clear messaging about transition timeline and security enhancements
  • Emphasis on continued compliance and data protection
  • Transparent communication approach

Implementation Timeline

The revised DMP emphasizes a clear transition timeline:

Phase Timeline Key Activities
Phase 1 Months 1-3 Planning, assessment, security framework establishment
Phase 2 Months 4-6 Pilot implementation with climate data
Phase 3 Months 7-9 Gradual health data migration with dual-system operation
Phase 4 Months 10-12 Complete transition to cloud for all new data

Benefits of Revised Approach

  1. Clarity for Ethics Review: Simplified document focused on data management rather than contracts
  2. Transparent Governance: Universal DAC requirements ensure equitable access
  3. Stakeholder Communication: Clear framework for informing data providers
  4. Transition Management: Explicit timeline and temporary nature of dual infrastructure
  5. Enhanced Security: Detailed security measures provide confidence during transition
  6. Operational Flexibility: Separating contact details allows easy updates without document revision

Document Review and Approval

This revised version incorporates feedback from the stakeholder meeting and has been structured to facilitate ethics committee review while maintaining comprehensive data management procedures.
