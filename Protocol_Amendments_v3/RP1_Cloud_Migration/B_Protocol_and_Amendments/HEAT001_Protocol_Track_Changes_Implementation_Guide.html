HEAT001 Protocol Track Changes Implementation Guide

DMP v1.0 → v2.2 Cloud Migration Changes for Protocol Amendment #2

📋 How to Use This Guide

  1. Navigate to the Protocol Section: Use the section references (e.g., "Section 5.1, page 12") to find the exact location in your protocol document
  2. Select and Copy Old Text: Highlight the text in the yellow "REPLACE THIS" boxes - this is exactly what appears in your current protocol
  3. Turn on Track Changes: Enable track changes in Word before making edits
  4. Replace with New Text: Delete the old text and paste the new text from the green "WITH THIS" boxes
  5. Verify Changes: Word will show deletions in red strikethrough and additions in blue underline
  6. Review Justification: Use the purple justification boxes for amendment documentation
⚠️ Important: These changes implement enhanced cloud infrastructure alongside existing UCT systems. All changes maintain POPIA compliance and strengthen data security measures.
Section 5.1: Data Management, Documentation and Curation
Location: Section 5.1, page 12
Change #1: Infrastructure Enhancement
🔍 REPLACE THIS:
Data will be managed and curated using UCT CSAG servers with on-premise storage and Jupyter Hub platform for analysis.
✅ WITH THIS:
Data will be managed and curated using UCT CSAG servers with on-premise storage and Jupyter Hub platform for analysis, enhanced by WHC-managed cloud infrastructure capabilities. The cloud infrastructure provides additional computational resources, automated backup systems, and enhanced security measures while maintaining compatibility with existing UCT systems.
Justification: To provide enhanced computational capabilities and improved data security through hybrid infrastructure approach while maintaining existing UCT capabilities.
Section 5.2: Data Security and Confidentiality
Location: Section 5.2, page 13
Change #2: Enhanced Security Measures
🔍 REPLACE THIS:
Data security will be maintained through standard university security protocols and access controls.
✅ WITH THIS:
Data security will be maintained through standard university security protocols and access controls, supplemented by cloud infrastructure implementing AES-256 encryption for data at rest and in transit, 24/7 Security Operations Center (SOC) monitoring, and automated threat detection systems. According to the rules of the Protection of Personal Information Act 4 of 2013 (as amended), data collected through cloud systems will be stored on secure servers which may be hosted outside of South Africa with appropriate safeguards.
Justification: To implement enhanced security measures exceeding minimum standards and ensure POPIA compliance for international data storage with appropriate safeguards.
🛡️ POPIA Compliance Note: This change specifically addresses cross-border data transfer requirements while maintaining full regulatory compliance through enhanced security measures.
Section 5.3: Network Firewall and Virtual Private Network
Location: Section 5.3, page 14
Change #3: Enhanced Network Security
🔍 REPLACE THIS:
Network security will be maintained through UCT institutional firewalls and VPN access controls.
✅ WITH THIS:
Network security will be maintained through UCT institutional firewalls and VPN access controls, complemented by cloud-based network security measures including distributed firewall protection, encrypted VPN tunnels, and network segmentation protocols that isolate research data from other network traffic.
Justification: To provide enhanced network security through multiple layers of protection and improved access management while maintaining existing UCT security infrastructure.
Section 5.4: Local Authentication and Authorization
Location: Section 5.4, page 15
Change #4: Enhanced Authentication Systems
🔍 REPLACE THIS:
User authentication will be managed through UCT Active Directory and role-based access controls.
✅ WITH THIS:
User authentication will be managed through UCT Active Directory and role-based access controls, integrated with cloud-based authentication systems providing multi-factor authentication, single sign-on capabilities, and granular permission management. Only the research team will have access to this data through verified authentication protocols.
Justification: To strengthen user authentication and provide enhanced access control mechanisms while maintaining integration with existing UCT directory services.
Section 5.5: Procedure for Making Data Available
Location: Section 5.5, page 16
Change #5: Enhanced Data Sharing Capabilities
🔍 REPLACE THIS:
Data will be made available to authorized researchers through UCT-managed access procedures following Data Access Committee approval.
✅ WITH THIS:
Data will be made available to authorized researchers through UCT-managed access procedures following Data Access Committee approval, enhanced by cloud-based data sharing platforms that provide secure data transfer, automated access logging, and real-time monitoring of data usage. Data will be anonymized using participant IDs and shared through encrypted channels with comprehensive audit trails.
Justification: To improve data sharing efficiency while maintaining security and providing enhanced monitoring capabilities, with strengthened anonymization and audit procedures.
Section 5.6: Data Analysis Platforms (if applicable)
Location: Section 5.6, page 17 (or equivalent data analysis section)
Change #6: Enhanced Analysis Capabilities
🔍 REPLACE THIS:

✅ WITH THIS:
Data analysis will be enabled through the CSAG/UCT Jupyter Hub platform, enhanced with cloud-based computational resources providing auto-scaling capabilities, containerized analysis environments, and integrated backup and version control systems.

Section 5.7: Data Storage and Archiving (if applicable)
Location: Section 5.7, page 18 (or equivalent storage section)
Change #7: Enhanced Storage Infrastructure
🔍 REPLACE THIS:
Data will be stored on UCT CSAG servers with standard backup procedures.
✅ WITH THIS:
Data will be stored on UCT CSAG servers with standard backup procedures, supplemented by cloud storage infrastructure providing automated daily backups with 30-day retention, geo-redundant storage, and disaster recovery capabilities with AES-256 encryption at rest.

🚀 Implementation Summary for HREC Submission

Key Amendment Points

  • Hybrid Infrastructure: Enhances existing UCT systems with cloud capabilities
  • Enhanced Security: Implements AES-256 encryption and 24/7 monitoring
  • POPIA Compliance: Addresses international data storage with appropriate safeguards
  • Improved Access Controls: Multi-factor authentication and granular permissions
  • Better Data Sharing: Secure platforms with comprehensive audit trails
  • Enhanced Analytics: Auto-scaling computational resources
  • Robust Backup: Automated daily backups with disaster recovery
Amendment Implementation: Upon receiving research ethics committee approval for this protocol amendment, the site will implement the protocol modifications in a phased approach over six months, ensuring continuity of existing operations while gradually introducing enhanced capabilities. A copy of the protocol amendment approval along with any correspondence will be retained in the site regulatory files for this study.
