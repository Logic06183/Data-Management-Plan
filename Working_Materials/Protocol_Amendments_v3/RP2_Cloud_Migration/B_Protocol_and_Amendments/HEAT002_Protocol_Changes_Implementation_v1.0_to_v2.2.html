HEAT002 Protocol Changes Implementation - Version 1.0 to 2.2

Study Focus: Early Warning System Development for Heat-Health Risk Assessment

Implementation Guide: Enhanced Cloud Infrastructure and Machine Learning Capabilities

Target Document: HEAT002 Protocol Version 1.0

Overview of Changes

This implementation guide provides exact text replacements to upgrade HEAT002 protocol from version 1.0 to version 2.2, incorporating enhanced cloud infrastructure, machine learning capabilities, and Early Warning System development requirements. All changes maintain POPIA compliance while enhancing computational capabilities essential for sophisticated heat-health predictive modeling.

Key Enhancement Areas for HEAT002

  • Enhanced computational infrastructure for machine learning model development
  • Real-time data processing capabilities for Early Warning System operations
  • Advanced analytics platforms with GPU acceleration
  • Multi-source data integration for comprehensive urban heat monitoring
  • Enhanced security measures for sensitive health data processing
  • Scalable cloud infrastructure supporting variable computational demands
  • Automated backup and disaster recovery systems

Protocol Text Replacements

Section 5.1 - Data Infrastructure
Old text: Data storage will utilise UCT on-premise infrastructure with standard backup procedures.
New text: Data storage will utilise both UCT on-premise infrastructure and WHC-managed cloud infrastructure with AES-256 encryption, providing enhanced scalability and disaster recovery capabilities whilst maintaining POPIA compliance. The cloud infrastructure provides enhanced computational resources essential for machine learning model development and real-time Early Warning System operations.
Justification: Enhanced infrastructure is essential for HEAT002's Early Warning System development, providing the computational scalability required for real-time data processing, machine learning model training, and predictive analytics while maintaining robust data protection.
Section 5.2 - Health Data Management
Old text: The Original Study Data is currently held under strong access control on servers hosted at UCT.
New text: The Original Study Data is currently held under strong access control on servers hosted at UCT, but from the start of Year 5, the data will shift to be stored on WHC-managed cloud infrastructure with AES-256 encryption, providing enhanced scalability and disaster recovery capabilities whilst maintaining POPIA compliance. This enhanced infrastructure supports real-time health data processing essential for Early Warning System development.
Justification: Cloud infrastructure provides the computational power and real-time processing capabilities essential for developing predictive models that link heat exposure to health outcomes in the Early Warning System.
Section 5.3 - Climate Data Integration
Old text: The data will be stored on IBM Research Africa and CSAG/UCT systems.
New text: The data will be stored on IBM Research Africa and CSAG/UCT systems. Relevant datasets, or subsets of datasets, will also be stored on the WHC-managed cloud services to allow for the association/linkage with the health datasets and to support real-time climate data processing for the Early Warning System.
Justification: Real-time climate data integration is critical for Early Warning System functionality, requiring enhanced cloud-based processing capabilities for immediate heat hazard assessment and alert generation.
Section 5.4 - Socio-economic Data Enhancement
Old text: This data will be stored on the CSAG/UCT systems.
New text: This data will be stored on the CSAG/UCT systems, while a copy will be stored on the WHC-managed cloud services to enable enhanced geospatial analysis and integration with urban heat monitoring systems for Early Warning System development.
Justification: Enhanced geospatial analysis capabilities are essential for identifying vulnerable populations and areas for targeted Early Warning System alerts, requiring cloud-based computational resources for complex urban heat modeling.
Section 6.1 - Data Processing Platform
Old text: Data indexing and processing (harmonization, homogenization, normalization) will be facilitated through the CSAG/UCT platform.
New text: Data indexing and processing (harmonization, homogenization, normalization) will be facilitated through both the CSAG/UCT platform and WHC-managed cloud infrastructure with enhanced processing capabilities and automated backup systems. The cloud infrastructure provides GPU acceleration for complex machine learning algorithms and real-time data processing essential for Early Warning System development.
Justification: Enhanced processing capabilities with GPU acceleration are essential for developing sophisticated machine learning models that can process multiple data streams (health, climate, socio-economic) in real-time for Early Warning System functionality.
Section 6.2 - Database Management
Old text: Data management will be facilitated through the CSAG/UCT platform with standard database services.
New text: Data management will be facilitated through both the CSAG/UCT platform and WHC-managed cloud infrastructure with enhanced security and automated backup systems. Database population utilises cloud-native database services, providing automated backup and recovery systems with enhanced data integrity and disaster recovery capabilities essential for continuous Early Warning System operations.
Justification: Continuous Early Warning System operations require robust data management with automated backup and recovery systems to ensure uninterrupted service delivery for heat-health alerts and predictive modeling.
Section 7.1 - Security Measures
Old text: De-identification procedures will be conducted on UCT infrastructure.
New text: De-identification procedures will be conducted on both UCT infrastructure and WHC-managed cloud infrastructure with enhanced security monitoring and automated compliance reporting to ensure robust protection of participant privacy during machine learning model development.
Justification: Enhanced de-identification procedures with automated monitoring are essential when processing health data through machine learning algorithms for Early Warning System development, ensuring participant privacy protection throughout the analytical pipeline.
Section 7.2 - Network Security
Old text: The CSAG compute infrastructure benefits from UCT's comprehensive security policies.
New text: The CSAG compute infrastructure benefits from UCT's comprehensive security policies, and from the start of Year 5, from WHC-managed cloud security architecture with 24/7 Security Operations Centre (SOC) monitoring and advanced threat detection systems for improved security posture and compliance. Network security utilises UCT's Cisco firewall and cloud-native firewall services providing enhanced protection for Early Warning System operations.
Justification: Enhanced security monitoring is critical for protecting Early Warning System infrastructure from cyber threats, ensuring continuous operation of public health alert systems and protection of sensitive health data used in predictive modeling.
Section 7.3 - Authentication and Access Control
Old text: Beyond UCT's broader security measures, the CSAG/UCT platform employs additional authentication and authorisation protocols.
New text: Beyond UCT's broader security measures, the CSAG/UCT platform employs additional authentication and authorisation protocols alongside cloud-specific access controls and automated compliance reporting for streamlined governance oversight during the transition period. Multi-factor authentication and role-based access controls ensure secure access to Early Warning System development environments.
Justification: Enhanced authentication protocols are essential for securing access to machine learning development environments and Early Warning System infrastructure, protecting sensitive health data and ensuring only authorized personnel can modify predictive models.
Section 8.1 - Data Access Procedures
Old text: All projects, regardless of whether they involve internal HE2AT Center Consortium members or external researchers, must go through the DAC for data access approval. This ensures equitable data sharing and maintains comprehensive tracking of all projects using the data.
New text: All projects, regardless of whether they involve internal HE2AT Center Consortium members or external researchers, must go through the DAC for data access approval. This ensures equitable data sharing and maintains comprehensive tracking of all projects using the data. Additional legal and compliance review will be conducted by UCT legal counsel or WHC legal representative to ensure all changes maintain legal compliance and align with institutional obligations before final approval. Enhanced cloud-based data sharing platforms provide secure collaborative environments for Early Warning System development with real-time access monitoring and automated audit trails.
Justification: Enhanced data access procedures support collaborative Early Warning System development while maintaining strict governance oversight, enabling secure sharing of development environments and predictive models with authorized research partners and public health agencies.

Amendment Summary

These changes transform HEAT002 from a basic data management approach to a sophisticated cloud-enabled Early Warning System development platform. The enhancements provide:

  • Computational infrastructure capable of real-time heat-health risk assessment
  • Machine learning platforms for developing predictive models
  • Enhanced security measures protecting sensitive health data during complex analytics
  • Scalable resources supporting variable computational demands during extreme heat events
  • Collaborative platforms enabling multi-institutional Early Warning System development
  • Automated systems ensuring continuous operation and data protection

POPIA Compliance Note: All cloud storage will be subject to appropriate safeguards for international data transfer as required by the Protection of Personal Information Act 4 of 2013. Data collected through cloud systems will be stored on secure servers which may be hosted outside of South Africa, with appropriate contractual and technical safeguards in place.

Implementation Timeline: Upon receiving research ethics committee approval for this protocol amendment, the site will implement the protocol modifications in a phased approach over six months, beginning with cloud infrastructure setup and progressing through machine learning platform deployment, Early Warning System development environment configuration, and operational system testing.
